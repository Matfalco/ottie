# 0041: More languages, and the system's language by default

Accepted 2026-10-15.

**Why:** Ottie spoke English and French. A device always kept the first language it found: Paraglide saves the language it detects, and the first device to load the page shared its own through the daemon, so a French phone could end up in English because a PC set it first.

**Decision** (Mathieu's choices):
- **Languages:** those of the EU, Latin America, the major ones of Asia and Africa. No Russian for now, and no Hebrew (removed 2026-10-15, Mathieu's choice, for the same kind of reason). They come in batches, a slice each; Arabic comes last, in its own slice, because the whole layout has to be mirrored (right to left; Persian and Urdu came with it). The first batch: German, Spanish (Spain, `es-ES`), Latin American Spanish (`es-419`), Italian, Dutch, Polish, Portuguese (Portugal, `pt-PT`) and Brazilian Portuguese (`pt-BR`).
- **"System" is a choice, and the default.** The language picker (Settings, sign-in page) starts with "System (Français)": the page shows the language closest to the system's, else English. A language chosen on a device is kept by Ottie itself (`ottie.language` in the browser's storage, `ui/src/lib/languages.ts`), not by Paraglide: the page reads it through two custom strategies (`custom-chosen`, `custom-system`, in `ui/src/hooks.client.ts`) that save nothing, since Paraglide saves whatever its strategies return the first time.
- **Every window follows a choice made in another** (`followLanguage`, through the browser's `storage` event): the desktop app's tray menu stays loaded while hidden, so it reloads in the new language, as other tabs do.
- **The shared language can be "System" too:** in `PATCH /settings`, `"language": null` puts every following device back on its own system's language, and `null` in `GET /settings` means that. A following device no longer shares its own language when none is shared (it still does for the look).
- **Matching a system's language to ours** (`closestLanguage`, the system's order of preference): the exact tag, then a stand-in, then the bare language. `es-MX` and every other Spanish with a country besides Spain → `es-419`; plain `es` and `es-ES` → Spain's. `pt-BR` → Brazil's; plain `pt` and every other country (Angola, Mozambique…) → Portugal's. Chinese (later) by script: `zh-TW`, `zh-HK`, `zh-MO` and `zh-Hant` → traditional, the rest simplified. The tray (`app/src/texts.rs`) gets the page's own tag, so it takes the exact file, else the bare language.
- **Translations not yet checked by a native speaker say so:** under the picker, "No native speaker has checked this translation yet. Help improve it", linking to the project's issues (later a platform like Weblate). `REVIEWED` in `languages.ts` lists the checked ones (English, French). The desktop app opens Ottie's own pages on GitHub in the system's browser; no other link leaves the window.
- **Counts without plural forms:** languages like Polish need several plural forms ("2 pobrania", "5 pobrań"). Rather than plural variants (the page's messages can have them, the tray's Rust texts can't), translations say counts as a label: "Pobierane: {count}", "Zaznaczone pobierania: {count}", as English and French already mostly do.
- **Tests:** every file in `ui/messages/` has every English message with the same placeholders, a name in the picker, and a locale in `project.inlang`; every file in `app/messages/` has the same texts and placeholders as English, all the way down.
- **The second batch** (slice L2): the rest of the EU in Latin script, Swedish, Romanian, Czech, Hungarian, Danish, Finnish, Slovak, Croatian, Slovene, Lithuanian, Latvian, Estonian, Irish and Maltese, as bare tags (`sv`, `ro`…). Each follows its own conventions: its quotation marks („…“, ”…”, »…«), the formal or the familiar "you" as its software usually does, and the tray's separators, units and durations as the page's `Intl` writes them (Hungarian "MB/mp", Finnish "Mt/s"), with one form for every count (Romanian "h", not "oră"/"ore"). Where a name would need a case ending (Hungarian, Finnish), the text puts it after a colon instead: "Eltávolítás: {name}".
- **The third batch** (slice L3): Greek, Bulgarian and Ukrainian (`el`, `bg`, `uk`), with the formal "you", «…» quotes in Greek and Ukrainian and „…“ in Bulgarian, Greek's `;` as its question mark and `·` as its semicolon, Ukrainian's ’ as its apostrophe (з’єднання), and the tray's units and durations as `Intl` writes them ("kB/δευτ.", "kB/сек", "кБ/с").
- **Fonts** (until slice L5, see below): the first two batches are in Latin script, which Outfit and DM Mono cover (their `latin-ext` subsets hold ő, ș, ā, ħ…). For Greek and Cyrillic, Mathieu chose a second bundled pair, Manrope and JetBrains Mono (`@fontsource-variable`, about 180 KB together; a browser fetches only the subsets a page uses): close to Outfit's look and the same on every system, rather than the system's font. Pages in those languages use them throughout (`:root:lang(el|bg|uk)` in `app.css`), so a line never mixes two fonts, Latin file names included; elsewhere they come second in the stack, for language names like «Български» in the picker. Bulgarian pages keep Manrope's Bulgarian letterforms (the browser picks them from `lang="bg"`), as Bulgarian typography prefers. Both fonts also cover Vietnamese. Longer units made the speed presets three or two to a row: their columns now fit the longest label (counted in mono characters, a Chinese, Japanese or Korean one as two).
- **The fourth batch** (slice L4): Simplified and Traditional Chinese (`zh-Hans`, `zh-Hant`), Japanese, Korean, Indonesian, Hindi, Vietnamese and Turkish (`ja`, `ko`, `id`, `hi`, `vi`, `tr`). Traditional Chinese uses Taiwan's words (檔案, 資料夾, 伺服器) and 「…」 quotes, as do Japanese pages; Simplified Chinese uses “…”. The polite or formal register software uses in each: です/ます, 합니다, "Anda", "आप", "bạn"; Turkish buttons in the imperative (İndir) and sentences with "siz". Chinese, Japanese and Korean count with their counters ("{count} 个", "{count} 件", "{count}개"); Korean never puts a particle right after a name (its form depends on the name's last sound): "편집: {name}", as Turkish never puts a case ending on one: "Kaldır: {name}". The tray's units, durations and percent as `Intl` writes them ("kB/秒", "1.5kB/s" in Korean, "%45" in Turkish).
- **Fonts for the fourth batch** (until slice L5, see below): Vietnamese pages use Manrope + JetBrains Mono throughout, as Greek and Cyrillic ones do; Turkish and Indonesian are in Outfit's Latin. For Hindi, Chinese, Japanese and Korean, Mathieu chose bundled Noto Sans (Devanagari, SC, TC, JP, KR) over the system's fonts, the same on every system, and then, since the whole fonts weigh ~18 MB and the UI is packaged in `ottie-api` (crates.io takes 10 MB at most), cut them to **the characters our translations use**: their messages, their name in the picker, what the page writes through `Intl` in that language (units, dates, weekdays, hours) and printable ASCII. That's ~760 KB for the five. `pnpm --filter ui fonts` (`ui/scripts/fonts.mjs`, with `subset-font`, HarfBuzz in WebAssembly) downloads them from Google Fonts at a fixed commit and writes `ui/src/fonts/`: one `.woff2` per language, keeping the copyright and licence (SIL OFL) inside, and `faces.css`, whose `unicode-range` lists what each holds. A test fails when a language's messages hold a character its font lacks (run the script again) or a language in those scripts has no font. A page in one of these languages starts with its own Noto, Latin letters and digits included, so a line keeps one font, and the mono font takes its characters from it ("kB/秒"); a character the font lacks (in a file name, say) comes from Outfit or Manrope, else the system's font for the page's language. Elsewhere the five come after Manrope in the stack, for the picker's names, each in its own language's letterforms (`option[lang]`). Korean pages break lines between words (`word-break: keep-all`). The lighter fonts (Outfit, DM Mono, Manrope, JetBrains Mono: ~260 KB, split by script) stay whole: they also draw file names in any Latin, Greek or Cyrillic language.
- **The fifth batch** (slice L5): Swahili, Amharic, Hausa, Yoruba and Zulu (`sw`, `am`, `ha`, `yo`, `zu`). Hausa in its Latin spelling with the hooked letters (ɓ ɗ ƙ), Yoruba with every tone mark (ẹ́, ọ̀), Amharic in Ethiopic script with «…» quotes and its own punctuation (። ፣ ፦), short imperatives on buttons and the polite form in sentences; the others with “…” quotes and imperative buttons, as their software usually has them.
- **Numbers and dates where the browser lacks a language:** Chrome, Edge and the desktop app's WebView2 have no `Intl` data for Hausa, Yoruba or Zulu, and `Intl` then silently uses the system's language ("1,5 Mo/s", "lundi" on a French PC). Those pages write numbers, units and dates in their country's English instead, in every browser (`intlLocale` in `ui/src/lib/languages.ts`: `en-NG` for Hausa and Yoruba, `en-ZA` for Zulu), and the tray's texts follow them. Swahili and Amharic have their own data. Swahili's units are long ("kilobaiti 300 kwa kila sekunde"), so the title bar has one more fold: once everything else is folded, the speed's chip shortens with "…" and its limit popup stays in the window.
- **The sixth batch** (slice L6): Arabic, Persian and Urdu (and Hebrew until 2026-10-15), written right to left: their pages are mirrored (`docs/decisions/0042`).
- **Fonts, revised in slice L5:** Mathieu chose to embed **only Outfit and DM Mono** (0021's pair) for now. Manrope, JetBrains Mono and the Noto fonts cut to our translations are gone, with `pnpm --filter ui fonts` and its script. A page in a language Outfit can't fully draw (Greek, Bulgarian, Ukrainian, Vietnamese, Hindi, Chinese, Japanese, Korean, Amharic, Hausa, Yoruba) uses the system's fonts throughout, its monospace one too (`:root:lang(…)` in `app.css`), which the browser picks for the page's `lang`, so a word or a line never mixes two fonts; elsewhere the system's fonts draw only what ours lack (a Greek file name, «Български» in the picker, "→"). A test checks the `:lang()` list against the characters Outfit draws; CLAUDE.md has the table. The built UI is now ~1.9 MB.

**Alternatives:**
- Paraglide's `localStorage` and `preferredLanguage` strategies: they can't tell "System" from a choice, since the first detected language is saved.
- Plural variants in messages: correct, but they need the raw number (counts are passed formatted), and the tray would need plural rules in Rust too.
- One Spanish and one Portuguese: fewer files, but Latin American and Brazilian users expect their own.
- Plain `es`/`pt` going to Latin America/Brazil (most speakers): Mathieu chose Spain's and Portugal's for the bare tags.
- Holding back languages until a native speaker checks them: they ship now, marked as unreviewed.
- For Hausa, Yoruba and Zulu, their own number and date data where the browser has it (Safari, WebKit on Linux), the stand-in elsewhere: real forms for some, but a page that differs from one browser to another, and a tray that can follow only one of them.
- Keeping the bundled fonts, and adding Noto Sans Ethiopic and Noto Sans (for Hausa and Yoruba) cut the same way: one look on every system, but ~1 MB more and a script to run after each change to those translations. Mathieu chose Outfit and DM Mono alone for now.
- For Chinese, Japanese, Korean and Hindi, the system's fonts (nothing bundled; native looking, but different on each system, and missing on a Linux without Noto CJK) or the whole Noto fonts (every character, but ~18 MB, too big for the crate on crates.io). Cutting them to our messages plus each language's everyday characters (~4–5 MB) would cover most file names too; Mathieu chose the messages only.
