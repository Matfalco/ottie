# 0034: The tray

Accepted 2026-10-14. Amends `docs/decisions/0017` (closing the window).

**Why:** a download manager runs for hours. With only a window, closing it stopped every download the app's daemon was running.

**Decision** (Mathieu's choices):
- **Closing the window hides it** and Ottie goes on in the tray. A switch in Settings → Desktop app (desktop app only) makes closing quit instead. "Quit Ottie" in the tray menu always quits: it stops the daemon the app started, as closing did before. The window is hidden, not destroyed, so it comes back at once, as it was.
- **A click on the icon opens the window; a right click opens Ottie's own menu.** The system's tray menus only hold text items, check marks and submenus, and the menu has the total limit's field, so Ottie draws it: a small borderless window (`app/src/popup.rs`) on the daemon's `/tray` page (`TrayMenu.svelte`), opened beside the click, inside the screen's work area, hidden when it loses focus or on Escape. It's created at the first right click, then hidden and shown again, so it opens at once. The page says how tall it is (`menu_ready`), and the app sizes and places the window from that.
  - **Its items:** Open Ottie; a status line ("2 downloading, 5 waiting · 1.5 MB/s", "Nothing downloading"); the running downloads as on the dashboard (name, speed, bar, "12 MB of 40 MB · 1.2 MB/s · 2 min left"), three at most, then "+2 more downloading" (never "+1": that one is shown instead); Pause all; Resume all; the total limit as in the title bar (switch, field, unit) with standard rates under it (256 kB/s, 512 kB/s, 1, 2, 5, 10, 20, 50 MB/s, the one in force lit); Quit Ottie. Picking an item closes the menu; the limit's controls don't.
  - **Pause all** pauses the waiting downloads first, then the running ones, so a freed slot doesn't start one of them. **Resume all** resumes paused downloads, not failed ones, which need a look first. Both use the usual `POST /jobs/{id}/pause|resume`.
  - The page is a front end like any other: it talks to the daemon through `api.ts`. From the app it only uses `menu_ready`, `show_main`, `quit_app` and hiding its own window.
- **The standard rates are in the title bar's limit popup too** (`RatePresets.svelte`, `LIMIT_PRESETS`).
- **The system's menu is still there when Ottie's can't be:** while the daemon can't be reached (Ottie's menu is its page), and always on Linux, whose trays report no clicks. It has the same items as text (the status line greyed, and under it, while running downloads have a known size, how far they have come together: "45% · 8 min left"), "Limit speed to …" as a check item (off, or back on at the last limit set, by anyone, as the events show it; 10 MB/s at first, like the page), and "Change the limit" with the standard rates and "Other…", which opens Ottie's menu at the pointer.
- **The Rust side follows the daemon,** as 0017 planned, for the system's menu, the tooltip (Windows: "Ottie", the status line, then the progress line as in the system's menu) and notifications later (5i). The app is a client of the API like any front end: it follows the events WebSocket (`tokio-tungstenite`), lists the jobs and settings again after `resync`, measures the speed from progress the way the page does, and reconnects every 2 s when the daemon goes away ("Connecting to Ottie…").
- **Its texts** come from `app/messages/{en,fr}.json`, one file per language like the page's. The page tells the app its language each time it loads (`set_language`), so the tray follows the page even on a device that doesn't follow the shared language.
- **The app's own settings** (closing, language, last limit) are saved in `app.json` in the app's config folder, beside `player.json`. The page reads and changes the closing switch through two app commands (`desktop`, `set_close_to_tray`).
- **The icon** is the drawn monochrome one (`res/icons/png/tray`): white on a dark taskbar, black on a light one. On Windows, the app reads the taskbar's own mode from the registry (`SystemUsesLightTheme`, through `windows-registry`, already built for reqwest's proxy detection) every second, and picks the drawn size for the display's scale (16 px at 100 %). macOS gets the black one as a template icon; Linux gets the white one, since most panels are dark and there's no common way to ask.

**Alternatives:**
- Only the system's menu, with the standard rates in a submenu and "Other…" opening the main window's limit popup: less code, but no field in the menu, which Mathieu wanted.
- The page running the whole tray (the window kept alive and hidden, labels pushed through an app command): one translation source and less Rust, but the tray would depend on the page being loaded and signed in, and notifications would too.
- Always hiding to the tray, without a setting: simpler, but some people expect the close button to quit.
- The colour app icon in the tray: readable everywhere without detection, but not the icons drawn for it.
- Polling `GET /jobs` instead of the events stream: no WebSocket client, but a long list fetched every second.
